# Over My Dead Body · 醉隱

更新日期：2026-10-20。**主線規則為「醉態解謎」**（`rules: "chill-puzzle"`），本文以它為準。三天醉意量表版與更早的 J／L 規則仍可載入，只作比較與參考，見附錄。

## 產品與範圍

吉姆加班後醒來，只想回家睡覺，卻走了七天。遊戲為網頁平台跳躍原型，固定鏡頭、單畫面房間。喝醉時會出現「醉影」幫他回家：醉階越高，醉影的招式越長，但幻覺也會改變地圖。

解謎核心是**時間差**：換醉階時，技能立刻改變，世界卻晚三秒才跟上。玩家利用這三秒，借還沒消失的舊地形，或在新地形出現前先出手。

目前內容為三天、每天 5 間，共 15 間。每天多一招：第一天只有「丟」，第二天加上「衝」，第三天加上「升天」。完整七天劇情尚未完成。上一版的一晚 7 間保存在 `prototype/legacy-chill-night.json`。

遊戲與編輯器各為獨立 HTML，透過 `drunken-rooms` v2 JSON 交接。遠端美術與字型需要網路，不能保證完整離線呈現。

## 試玩

解謎模式會讀取同資料夾內的兩個 JSON，需要 HTTP 伺服器。從專案根目錄執行：

## 操作

| 按鍵 | 行為 |
|---|---|
| A / D | 左右移動 |
| W / 空白鍵 | 跳躍 |
| E | 喝一口，升一階；靠近 NPC 時優先交談 |
| K | 原地放屁，降一階；不會推動身體 |
| J | 醉影，依目前醉階自動演完整招 |
| R | 重來本間 |
| P | 醉影帶路：從出生點自動通過本間，進下一間後交回控制；再按 P 中途接手 |

### 手機觸控

手機與平板（粗略指標裝置）會顯示半透明按鈕：左下方向鍵，右下「跳」與「J 醉影」，右側「E 喝一口」「K 放屁」，右上「帶路」（P）、「重來」（R）、「選單」（Esc）。點一下遊戲畫面等於 Enter，用來跳過每天的開場與結尾。直放時遊戲畫面在上、按鈕在下，並提示橫放。

### BeaverKit

已發布為「醉隱」：https://beaverkit.io/p/I6IdRlKpC2B（知道連結的人都能看）。更新時先執行 `node handoff/kit/build-beaverkit.mjs`，再到 BeaverKit 作品的編輯頁匯入 `prototype/beaverkit.html`。作品在沙盒 iframe 裡執行，localStorage 不可用，遊戲已能在沒有它的情況下正常運作。

## 規則

### 醉階

- 醉階為 0～3：清醒、微醺、大醉、爛醉。上限是當天的 `cells`（第一天 1、第二天 2、第三天 3）。房間的 `booze` 是進場醉階。
- **清醒（0 階）叫不出醉影**：按 J 只會說「還不夠醉」，不算用掉這次離地的招式。
- 醉階不會自動回復或消退，也沒有酒瓶，只由 E／K 改變。
- 以下情況不能換階：上一次切換的倒數還沒結束、有延後出現的地形、醉影連段中、正被舉起或衝刺中。

### 巡邏保全（解謎模式）

- 保全腳下的地形消失時（例如 K 後三秒橋消失），他會往下掉；落在碎玻璃上或掉出房間就會被撞飛。
- 新出現的實心格若會壓到保全，那一格延後出現，等他走開。
- 覆蓋層不會改動保全出生的那一格。

### 三秒時間差

- 按下 E／K 時，醉階與技能**立刻**改變。
- 地圖保留舊醉階的樣子，**三秒後**才切換成新醉階的覆蓋層。人在空中也照常切換。
- 倒數期間不能再換階，也不能取消或延長倒數。
- 新出現的實心格若會夾住吉姆或醉影，只有那一格延後，等不重疊時才出現；其他格子照時間切換。
- 幻覺地形（與 0 階不同的格子）以紫色呈現，即將改變的格子會閃爍。

### J：醉影

J **不消耗醉階**，招式依「身體」的醉階決定，與地圖目前的樣子無關。因此倒數期間，可以用新醉階的招式搭配舊地圖。

| 醉階 | 連段 |
|---|---|
| 0 | 叫不出來 |
| 1 | 丟 |
| 2 | 衝 → 丟 |
| 3 | 升天 → 衝 → 丟 |

- 每次離地只能用一招；落地且連段結束後恢復。
- 方向為按下 J 當下的面向（按 J 時同時按 A／D 可轉向），連段中不會再轉向。
- 丟固定為一般弧線，沒有高拋／低飛。被丟出後，A／D 仍可微調；撞到牆時按住朝牆的方向，越過牆頂後會被帶上去。
- 衝刺中不能跳離。衝刺撞到牆會立刻停下，接著往上丟。
- 升天會破壞頭上的箱子（`B`／`C`）。衝刺可撞破擋路的箱子、撞飛巡邏角色、踩過碎玻璃。丟不會破壞箱子。
- 醉影扛人需要約 4 格的頭頂空間，不夠時 J 不會發動。升天後若頭頂只剩不到 4 格，同樣扛不起來：**雨棚離地 8～11 格時，爛醉的 J 會升天後卡住**；大醉的衝照常可用。

### 設計用的距離（格，1 格 = 40 px，從地面量）

| 動作 | 最高 | 最遠 |
|---|---|---|
| 跳 | 2.8 | 5.4（助跑 6.3） |
| 丟 | 7.8 | 16.7（按反方向可縮到約 4.4） |
| 跳起來再丟 | 10.6 | 21 |
| 衝 → 丟 | 9.8 | 約 29（衝 12 格後才丟） |
| 跳起來再衝 → 對牆丟 | 約 12.5 | 空中平飛約 8.8 格後才落下 |
| 升天 → 衝 → 丟 | 14.2 | 約 28 |
| 天花板 4 格高時丟 | 2.2 | 4.9 |
| 天花板 3 格高時丟 | 1.2 | 3.6（衝不出來） |

捷徑多半來自「跳起來再按 J」和「身體只要有一部分踩在邊上就算站著」。坑的有效寬度是坑寬減 1.1 格。

### 死亡、重來與瓶蓋

- 死亡或按 R：房間重置，回到出生點與進場醉階，進行中的招式與倒數一併清除。
- 已拿到的瓶蓋保留，不會重新出現。每間一個瓶蓋，都是選拿，主路設有安全地板。
- 每天最後一間通過後顯示當天的瓶蓋收集數。

### 畫面

只顯示醉階、目前的技能連段與切換倒數。房間的 `lines` 在解謎模式**不顯示**，只作為關卡設計註記；每天的新招改由當天開場文字（`intro`，可分行）教。

### 自動通關（P）

路線存在 `chill-routes.json`，以固定 240 Hz 重播，結果可重現。每條路線綁定房間簽章（規則、地圖 ID、`cells`、`abilities` 與整個房間物件）；房間任何欄位改動或匯入不同版本，路線就會停用。自動路線保證出關，不保證收齊瓶蓋。

## 十五間解謎房

三天都已依「解謎深度＋動態元素」重新設計（2026-10-21）：房名不給解法，每間有一個看似對但會失敗的做法，瓶蓋放在需要進階技巧的支線（每間的瓶蓋路線 `capPlans` 都有測試）。

每天的順序：先教新招，再教它跟三秒時間差的關係，最後一間把當天學到的東西串起來。

- 不換階過不了：除了 2-2（一進場就是大醉）以外的 14 間。
- 沒有三秒時間差過不了：1-3、1-5、2-3、2-5、3-3、3-4。

## JSON 契約

| 層級 | 欄位 | 說明 |
|---|---|---|
| 根物件 | `format`, `version`, `maps` | `"drunken-rooms"`、`2`、至少一張地圖 |
| 根物件 | `rules` | `"chill-puzzle"` 啟用醉態解謎規則；省略則依地圖 `cells` 判斷是三天版或舊 J／L 規則（附錄） |
| 地圖 | `id`, `name`, `intro`, `outro` | 識別、顯示名稱、開場與結尾文字；`intro` 可用 `\n` 分行，解謎版用它教當天的新招 |
| 地圖 | `cells` | 醉階上限 1／2／3；解謎模式必填 |
| 地圖 | `abilities` | 能力 ID 陣列；設定 `cells` 時可省略，現有解謎資料填 `["wrestler"]` |
| 地圖 | `rooms` | 非空房間陣列 |
| 房間 | `id`, `name`, `theme` | 同一張地圖內 ID 不重複；主題為 `office`、`pantry`、`elevator`、`lobby` 或 `street` |
| 房間 | `tiles` | 18 個字串，每個長度 32，恰好一個 `P` |
| 房間 | `booze` | 進場醉階 0～3（不超過當天 `cells`） |
| 房間 | `stages` | `"1"`／`"2"`／`"3"` 對應 18×32 覆蓋層，依醉階逐層疊加；`.` 保留、`_` 清空，其餘只接受 `#^=BC<>` |
| 房間 | `exits` | `left`、`right`、`top`、`bottom` 對應同一張地圖的房間 ID 或 `null` |
| 房間 | `portalTargets` | `"x,y"` 對應房間 ID 或 `null`，座標必須位於 `O` |
| 房間 | `portalTarget` | 房間級傳送門目的地（舊欄位；`build-chill.mjs` 用它把每天的房間依序串起來） |
| 房間 | `npcs` | `"x,y"` 對應對話物件，座標必須位於 `N` |
| 房間 | `lines` | 房間文字陣列；解謎模式不顯示 |

房間固定 32 × 18 格，遊戲每格 40 px，邏輯畫面為 1280 × 720。座標從左上角 `(0,0)` 開始。房間至少有一個邊緣出口或一個 `O`。所有非空出口目的地必須存在於同一張地圖。沒有出口的邊緣是牆，底部沒有出口則是死亡坑。

傳送門目的地依序使用：個別 `portalTargets["x,y"]` → `portalTarget` → 房間列表下一間 → 結束這一天。明確的 `null` 直接結束一天。

| 格子 | 用途 |
|---|---|
| `.` / `#` | 空白／地形 |
| `^` / `=` | 碎玻璃（致命）／木板（單向平台） |
| `B` / `C` | 可破壞箱子／站上去會崩落的紙箱 |
| `<` / `>` | 左／右輸送帶 |
| `R` / `L` | 巡邏角色（碰到即死）／經過下方時掉落的招牌 |
| `*` / `P` | 瓶蓋／出生點 |
| `O` / `N` | 傳送門／NPC |

### 路線檔 `chill-routes.json`

| 欄位 | 說明 |
|---|---|
| `stepHz`, `rules` | `240`、`"chill-puzzle"` |
| `rooms` | 以 `"地圖ID:房間ID"` 為鍵，內容為 `signature`（房間簽章）與 `steps` |
| `steps[]` | `{ frames, input }`；`input` 只接受 `left`、`right`、`jump`、`jumpPressed`、`down`、`kPressed`、`gradeUpPressed` 布林值與 `skill: "wrestler"`；總長上限 120 秒 |

## NPC 對話

每個 NPC 擁有獨立 `name`、`start` 與 `nodes`。`start` 必須指向既有節點。節點包含 `text`，以及可選的 `next` 或 `choices`；目的地為既有節點 ID 或 `null`（結束）。每節點文字最多 500 字元；回答最多 9 個，每個最多 100 字元。提供 `choices` 時陣列不可為空，每個回答需有 `text` 與 `next`。交談時角色與世界暫停，Enter 繼續，1–9 選擇回答。

```json
{
  "name": "同事",
  "start": "hello",
  "nodes": {
    "hello": {
      "text": "下班了？",
      "choices": [{ "text": "我要回家。", "next": "bye" }]
    },
    "bye": { "text": "路上小心。", "next": null }
  }
}
```

目前十五間解謎房都沒有 NPC。

## 關卡編輯器

`prototype/editor.html` 目前**不支援解謎模式**：沒有 `rules`、`cells`、`booze`、`stages` 的編輯介面，內建範例也是舊版。解謎房請改 `handoff/kit/` 的房間定義後重新產生。

編輯器現有功能：編輯畫布每格 30 px，左鍵畫格子、右鍵擦除、Shift 拖曳矩形；房間與日的編輯、排序、主題、出口、文字、NPC 視覺對話工具，以及個別傳送門目的地。資料自動儲存於 `drunk-editor` localStorage，復原最多 120 步並支援重做；localStorage 被封鎖時請匯出 JSON 留存。

「試玩目前房間」在 iframe 中載入 `game.html?editorTest=1`：遊戲送出 `drunk-test-ready`，編輯器回傳 `drunk-editor-test`，內容為 `campaign` JSON 字串、`mapIndex` 與 `roomId`。
