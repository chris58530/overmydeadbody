# Over My Dead Body · 醉隱

更新日期：2026-10-18。本文描述 `prototype/game.html` 與 `prototype/editor.html` 的目前實作；未實作的故事範圍另行標示。

## 產品與範圍

吉姆加班後醒來，只想回家睡覺，卻走了七天。遊戲為網頁平台跳躍原型，以固定鏡頭、單畫面房間與醉影連段為核心。目前預設內容為第一天 5 間、第二天 4 間、第三天 3 間，逐天開放 1／2／3 格醉意。完整七天劇情尚未完成。上一版 J／L 關卡保存在 `prototype/legacy-jl-days.json`，更早版本保存在 `prototype/legacy-days.json`。

遊戲與編輯器各為獨立 HTML，透過 `drunken-rooms` v2 JSON 交接。可直接開啟檔案；編輯器內試玩需要兩個檔案位於同一資料夾。遠端美術與字型需要網路，不能保證完整離線呈現。

1. 開啟 `prototype/editor.html` 編輯關卡，可按「試玩目前房間」測試尚未匯出的修改。
2. 按「結束試玩 · 返回編輯」繼續編輯，完成後按「匯出 JSON」。
3. 開啟 `prototype/game.html`，按 Esc →「載入關卡 JSON」，或將 JSON 檔案拖進遊戲畫面。

放置 NPC 後可點選角色，使用右側視覺對話工具編輯，或在「進階：對話 JSON」按「套用對話」及「匯入對話檔」。放置傳送門後，可點選傳送門或選取其座標，再設定個別目的房間或「結束這一天」。

## 七關醉態解謎

從專案根目錄啟動靜態伺服器：

```sh
python -m http.server 4174 --bind 127.0.0.1 --directory prototype
```

開啟 `http://127.0.0.1:4174/game.html?chill=1`。遊戲會讀取同資料夾內的兩個 chill JSON，因此此模式需要 HTTP 伺服器。未加 `chill=1` 時仍載入原本三天關卡。

- A／D 移動，W／空白跳躍；E 放空升一階，K 原地放屁降一階。
- 醉態固定在一至三階。J 不耗酒意，一階丟、二階衝→丟、三階升天→衝→丟，自動完成連段；每次離地一招，落地後恢復。
- 技能立刻隨醉態改變，地圖保留舊狀態三秒後切換，空中也照常切換。倒數期間不可再次調階；會夾住角色的新增實體延後出現。
- 七關依序為先試一下、橋下的門、借一下高台、末班貨梯、月台上的月亮、便利店的雨棚、家門口的天橋。主路設安全地板，瓶蓋為選拿。
- P 從出生點自動通過本間，進下一間後交回控制；再按 P 中途接手，R 重來。自動路線不保證收齊瓶蓋，修改或匯入不同版本的房間會停用路線。
- Esc 開啟操作說明與選關。畫面僅保留醉階、技能與切換倒數。

`handoff/kit/build-chill.mjs` 產生關卡；修改後執行 `node handoff/kit/build-chill.mjs`，再執行 `node handoff/kit/build-chill-routes.mjs` 重新錄製並獨立重播驗證全部路線。

## 三天關卡的遊戲行為

房間固定 32 × 18 格，遊戲每格 40 px，邏輯畫面為 1280 × 720。每間房間必須有且只有一個出生點。日／地圖決定醉意格數上限，房間決定地形、出口、場景與對話。

| 操作 | 行為 |
|---|---|
| A / D | 左右移動 |
| W / 空白鍵 | 跳躍 |
| J | 一次耗盡醉意；依滿格數自動演完：1 格丟、2 格衝→丟、3 格升天→衝→丟 |
| 舉起時 W / S | 摔角手改丟高拋／低平飛；不按為一般弧線，飛行中 A / D 可轉向 |
| 衝刺中 W | 從保鑣肩上跳離，保留大部分速度 |
| K | 點按放屁，每次扣 1/6 格、冷卻 0.14 秒；按住 A／D 向前加速，不按方向或按住 W 往上噴 |
| R | 重試房間 |
| P | 自動通關本間：從出生點重來，照內建路線過關並吃到瓶蓋，進下一間後交回控制；再按 P 或 R 取消 |
| E | 靠近 NPC 開始交談，交談中繼續 |
| Enter | 交談中繼續 |
| 1–9 | 選擇對話回答 |
| Esc | 暫停與關卡載入選單 |
| M | 靜音 |
| ` | 手感調整面板 |

醉意每秒自動回復 0.4 格，已拿掉酒瓶。J 依滿格數選連段並清空量表（包含未滿的餘量），連段期間暫停回復，之後再等 0.8 秒回復。K 只能點按；放屁會降低滿格數，可能讓 J 退成較短的連段。死亡回到該房間進場時的醉意。

滿格數也是醉階。地圖變化會先閃爍預告 0.9 秒，落地後才套用；預告期間點 K 降低醉階，可以取消尚未生效的升階。新的實心格若會壓到角色，會延後切換。第二天以箱牆要求衝刺，第三天以頂棚和高牆引導升天；第一天前兩間先練 K，後面練 J 與醉階。

沒有 `cells` 的舊關卡仍沿用 J 摔角手、L 保鑣，以及可切換的抽卡模式。下表與每次離地一次的限制適用舊關卡；新關卡由醉意量表決定能力。手感參數儲存在 `drunk-tuning-v3` localStorage。

| 能力 ID | 名稱 | 行為 |
|---|---|---|
| `wrestler` | 摔角手 | 舉起吉姆 0.22 秒，依方向與 W / S 選三種弧線拋出，飛行中可轉向 |
| `bodyguard` | 保鑣 | 扛著吉姆衝刺最多 1 秒（約 700 px），可破壞箱子、撞飛保全並通過碎玻璃；撞牆會彈回，地面衝刺中可跳離 |

每次離地限用一招；保鑣衝刺即使從地面發動也算用掉這一次。保鑣撞破箱子或撞飛保全時，空中使用次數與「作用中能力」會重置（有音效、閃光與台詞），可以接著再發動下一招。

畫面左下顯示當天能力，暫時不能用時變暗。舉起時與可跳離的衝刺中，角色頭上會提示可用按鍵。房間文字若含英文按鍵字母（如 J、W），會常駐於畫面底部作為該房提示。死亡時吉姆的鬼魂會飄起，並依死因（玻璃、坑、保全、招牌）說一句話；重落地時附近的 NPC 會被吵醒。

自動通關路線存在 `Drunk.AUTO`，每間預設房間一條，由求解器找出，以固定 240 Hz 重播，結果可重現。只有與內建版本完全相同的房間會啟用；修改或匯入的房間按 P 時，吉姆會說他不知道怎麼過。改動預設房間後需重新產生路線；測試會檢查每間都能吃到瓶蓋並出關。

房間出口可位於四個畫面邊緣，或使用接觸觸發的傳送門。目的地為同一天的房間 ID；`null` 表示結束這一天。日結束後確認進入下一天。NPC 交談時暫停角色與世界。

## 關卡編輯器

編輯畫布每格 30 px。支援左鍵畫格子、右鍵擦除、Shift 拖曳矩形，以及房間與日的編輯、房間排序、主題、能力池、出口與文字設定。

資料自動儲存於 `drunk-editor` localStorage；復原保留最多 120 個快照，支援重做。localStorage 被環境封鎖時無法保證保存，使用者應匯出 JSON 留存。

匯入接受 v2 JSON 與 32 × 18 房間尺寸，編輯器提供錯誤與警告檢查。試玩前必須通過錯誤檢查。匯出包含 NPC、個別傳送門目的地與所有房間；空的 `lines` 與舊 `notes` 欄位不輸出。

「試玩目前房間」以最新編輯內容建立快照，從選取的日與房間開始，在 iframe 中載入 `game.html?editorTest=1`。遊戲送出 `drunk-test-ready`，編輯器回傳 `drunk-editor-test`，內容為 `campaign` JSON 字串、`mapIndex` 與 `roomId`。每次重新開啟試玩更新快照，結束後返回編輯。

## JSON 契約

| 層級 | 欄位 | 說明 |
|---|---|---|
| 根物件 | `format`, `version`, `maps` | `"drunken-rooms"`、`2`、至少一張地圖 |
| 地圖 | `id`, `name`, `intro`, `outro` | 識別、顯示名稱、開場與結尾文字 |
| 地圖 | `abilities`, `rooms` | 非空能力 ID 陣列、非空房間陣列 |
| 地圖 | `cells` | 可選，1／2／3；設定後啟用新醉意玩法，`abilities` 可省略；省略則沿用舊 J／L 規則 |
| 房間 | `id`, `name`, `theme` | 同一天內 ID 不重複；主題為 `office`、`pantry`、`elevator`、`lobby` 或 `street` |
| 房間 | `tiles` | 18 個字串，每個長度 32，恰好一個 `P` |
| 房間 | `exits` | `left`、`right`、`top`、`bottom` 對應同一天房間 ID 或 `null` |
| 房間 | `lines` | 房間文字陣列 |
| 房間 | `booze` | 進場醉意 0～3，實際限制在當天 `cells`；死亡重置為進場值 |
| 房間 | `stages` | `"1"`／`"2"`／`"3"` 對應 18×32 覆蓋層，依醉階逐層疊加；`.` 保留、`_` 清空，其餘只接受 `#^=BC<>` |
| 房間 | `portalTargets` | `"x,y"` 對應房間 ID 或 `null`，座標必須位於 `O` |
| 房間 | `portalTarget` | 相容舊資料的房間級傳送門目的地 |
| 房間 | `npcs` | `"x,y"` 對應對話物件，座標必須位於 `N` |

座標從左上角 `(0,0)` 開始。房間至少有一個邊緣出口或一個 `O`。所有非空出口目的地必須存在於同一天。

傳送門目的地依序使用：個別 `portalTargets["x,y"]` → 舊 `portalTarget` → 房間列表下一間 → 結束這一天。明確的 `null` 直接結束一天。編輯器更改房間 ID 時同步更新目的地；刪除目的房間時將引用改為 `null`；擦除傳送門時移除該格目的地設定。

| 格子 | 用途 |
|---|---|
| `.` / `#` | 空白／地形 |
| `^` / `=` | 碎玻璃／木板 |
| `B` / `C` | 衝刺可破壞箱子／會崩落的紙箱 |
| `<` / `>` | 左／右輸送帶 |
| `R` / `L` | 巡邏角色／掉落物 |
| `*` / `P` | 瓶蓋／出生點 |
| `O` / `N` | 傳送門／NPC |

## NPC 對話

每個 NPC 擁有獨立 `name`、`start` 與 `nodes`。`start` 必須指向既有節點。節點包含 `text`，以及可選的 `next` 或 `choices`；目的地為既有節點 ID 或 `null`（結束）。每節點文字最多 500 字元；回答最多 9 個，每個最多 100 字元。提供 `choices` 時陣列不可為空，每個回答需有 `text` 與 `next`。

```json
{
  "name": "同事",
  "start": "hello",
  "nodes": {
    "hello": {
      "text": "下班了？",
      "choices": [{ "text": "我要回家。", "next": "bye" }]
    },
    "bye": { "text": "路上小心。", "next": null }
  }
}
```

編輯器提供視覺節點／回答工具、起始節點與目的地選單、分支試播，以及進階 JSON 編輯與檔案匯入。修改自動保存並支援復原／重做；擦除 NPC 格子移除其對話。
